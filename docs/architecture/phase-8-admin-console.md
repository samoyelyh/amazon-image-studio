# Phase 8：管理后台、监控与安全验收

## 功能定位与优先级

- 功能名称：平台管理后台
- 所属模块：管理后台
- 优先级：P1（用户、团队、额度、API Key、资源池），P2（队列监控、系统日志）
- 依赖：Phase 3 账号与团队、Phase 5 额度系统、Phase 6 异步任务与资源池、Phase 7 工作台接入
- 复用原则：继续使用 FastAPI、MySQL、Redis、Celery、对象存储、统一权限、统一额度、统一任务和统一资源池，不建立第二套管理系统。

## 功能目标与操作流程

平台管理员进入 `/admin` 后可以：

1. 查看用户、团队、任务、额度和可用资源总览。
2. 停用或恢复用户与团队，授予或取消平台管理员角色。
3. 创建团队并对指定团队调整额度；调整结果进入统一额度流水和审计日志。
4. 按 Provider → 模型 → 资源池 → API Key → 绑定的顺序配置中转站。
5. 查看 Celery 队列深度和全平台任务状态，定位限流、超时、重试和失败。
6. 查看操作审计与登录安全日志。

API Key 只在创建表单中输入一次。浏览器将其直接提交到服务端资源池接口；服务端加密存储，后续管理接口只返回掩码和指纹，不返回密文或明文。

## 输入与输出

- 用户/团队：状态、平台角色、团队名称和唯一标识。
- 额度：目标团队、正负调整数值、原因、客户端生成的幂等键。
- Provider：编码、名称、适配器类型、Base URL。
- 模型：内部编码、上游模型名、能力列表和可选配置。
- 资源池：模型、作用团队、优先级、权重。
- API Key：Provider、作用团队、标签、密钥、并发/RPM/日限额。
- 输出：管理视图、资源状态、任务队列指标、额度结果与审计记录；不产生图片和素材。

## 权限、数据模型与兼容性

- 所有 `/api/v1/admin/*` 接口必须具备 `platform.admin` 权限，前端隐藏入口不能替代后端校验。
- 当前管理员不能停用自己，也不能取消自己的平台管理员权限。
- 停用用户或团队时撤销相关 Refresh Token，避免旧会话继续刷新。
- 团队额度调整调用现有 Billing Service，保留额度账户、流水、幂等和审计语义。
- 资源启停复用 `providers`、`provider_models`、`resource_pools`、`api_keys` 表。
- 本阶段没有新增表或必填字段，不需要 Alembic 迁移，对旧用户、旧团队、旧任务和旧资源兼容。

## 接口设计

- `GET /admin/overview`
- `GET/PATCH /admin/users[/{id}]`
- `GET/PATCH /admin/organizations[/{id}]`
- `POST /admin/organizations/{id}/quota-adjustments`
- `GET /admin/resources`
- `PATCH /admin/providers/{id}`、`/models/{id}`、`/resource-pools/{id}`、`/api-keys/{id}`
- `GET /admin/jobs`、`GET /admin/queues`
- `GET /admin/audit-logs`、`GET /admin/login-audits`

创建 Provider、模型、资源池、API Key 和绑定关系继续调用 Phase 6 的资源池接口。权限、组织隔离、参数校验和 Provider 一致性由服务端重新检查。

## 异常与安全规则

- 未登录返回 401，无平台权限返回 403，自锁操作返回 409。
- 额度不足、重复幂等键、非法数值沿用统一额度错误码。
- API Key 不写入 URL、日志、审计元数据或管理接口响应。
- Redis 不可用时队列接口降级返回数据库统计并标记 `redis_ok=false`，不阻断其他后台功能。
- 上游 Key 无可用资源、限流、冷却和并发占用继续由统一资源池选择器处理。
- 页面提供加载、空数据、错误、移动端横向滚动与暗色模式。

## 测试与验收标准

自动化覆盖：平台权限、自锁保护、用户停用与恢复、团队额度调整、幂等与审计、Key 掩码、资源启停、全局任务/队列/登录日志、前端请求路径和 Key 请求体隔离。并继续执行全量后端、全量前端、生产构建和 Alembic 检查。

可执行验收：

1. 使用平台管理员账号登录并进入 `/admin`。
2. 总览显示用户、团队、额度、任务和资源数量。
3. 创建测试团队并调整额度，团队余额和审计日志同步更新。
4. 配置中转站 Provider、模型、资源池和 API Key；刷新页面后只看到 Key 掩码。
5. 将 Key 绑定资源池，资源清单显示绑定数量。
6. 提交工作台任务后，队列和任务页能够恢复并显示进度。
7. 普通成员访问管理接口得到 403，且无法读取其他团队数据或 Key。
8. Redis 或 Worker 异常时后台给出明确状态，已有任务和额度记录不丢失。
