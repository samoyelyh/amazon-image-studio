本轮保留原 SkillRegistry、MCP Gateway、Composer、Asset、JobBatch、Worker、Provider 与权限服务。Main 作需求与任务归属决策，专业 Executor 同次提交市场判断、购买理由、创意概念和设计；没有新增串行的创意总监规划模型。Executor 在同次策划调用中可看到真实商品原图，不必依据视觉摘要猜裁切位置。没有进入 LangGraph 的 `plan_intent`、`build_chat_plan` 或 `build_dynamic_plan` 主路径。

新增契约让每条理由说明 `priority_rationale`、`evidence_boundary`，整套说明 `priority_method` 和 `rejected_reasons`。五条候选可共用事实、合并弱细节，或设为 `internal_only`。创意增加商业命题、可执行视觉机制与商品专属性；每槽位明确目的、位置/占比、镜头、光线、层级、原生文字结构和与其他槽位的差异。`rule_applications` 记录 Skill 原则对应的具体动作；原则 ID 由这些动作推导，避免重复填写触发付费修正。

DSH 本次实际产出的暂定排序依据是“商品差异性、穿着用途相关性、可见事实强度、画面可表达性”，明确不代表热销或消费者普遍偏好。本轮没有取得新市场样本，MCP 调用为0，未重发历史 ASIN 请求。

| DSH购买理由候选 | 本次实际依据 | 质量审阅 |
|---|---|---|
| 1 城市归属感表达 | Seattle图形与原有“YOU'RE MY HOME”文字 | 有消费者价值；归属动机仍是创意假设 |
| 2 藏青到青绿的渐变外观 | 原图可见配色 | 可作风格价值；“独特”不能冒充市场差异性研究 |
| 3 背面姓名/号码的个人化联想 | 原图YOUR NAME/00 | 可讲球衣式外观；未证实定制服务，隐含定制措辞仍需收紧 |
| 4 连帽/袋鼠口袋的休闲形态 | 可见常规结构 | 价值仍偏弱，应作为使用佐证，尚未成为强购买理由 |
| 5 正背面统一表达 | 同一原图的前背设计 | 已设为内部理由，不再强占一个公开主卖点 |

本轮主题为 **You're My Home · 暮色西雅图**。原生 DSH 先生成“城市轮廓与商品轮廓对话”的方案，但首轮主视觉仍是人物与城市背景。人工验收指出这一点后，向同一Ticket反馈“只重做主视觉，采用非人物编辑式静物/图形关系”。DSH 独立作出平铺商品、背号局部与弧形色带的具体构图，实际新图执行了这一安排。**这包含一次人类艺术指导反馈，不能当作零反馈自主设计已通过。**

| 模块 | 实际设计与交付 | 质量判断 |
|---|---|---|
| 1 主视觉 | 970×600；左侧卫衣静物，右上背号局部，青绿弧线连接；原生标题在图外 | 有具体图形关系，已摆脱站立模特套路；商品自身小字仍有重绘风险 |
| 2 渐变亮相 | 600×600挂拍与左右图文 | 配色识别清楚，镜头仍偏普通商品展示 |
| 3 使用关系 | 三张600×600；整理帽兜、坐姿持杯、背面行走，独立文案 | 动作与视角有变化，城市背景与色温仍相近 |
| 4 原图证据 | 600×800与600×350；直接裁切原始Logo和背号，不调用生图 | 源图保真改善；源区域仅251×191、264×244，需要放大，纵向槽位留白偏多 |
| 5 收束 | 600×600正面静物与原生短句 | 识别一致，但与模块2仍有完整商品视图重复 |

最终交付是5个模块、8个槽位：最新6张生成图和2张原图裁切。实际共调用7次图片API，包含首轮6张与主视觉局部修改1张。修改后其余5个生成槽位的Output ID不变，两个原图槽位的裁切、源文件哈希和像素处理记录不变，父版本链保留。

原图复用通过已有会话和Asset权限读取，只接受归一化矩形，在现有原生模块和ZIP中交付；无任意文件路径、Shell、SQL或新生图引擎。两处源文件SHA256均与用户Seattle.png一致，操作为裁切、等比缩放和画布适配，**没有生成重绘，也不等于输出像素逐点不变或拥有真实高分辨率细节。**

实际Job检查显示，7次图片执行中的槽位设计字段、Skill设计动作均进入实际Prompt。局部修改同步更新权威槽位设计，避免只改composition而旧camera继续生效。Composer去除了v2中通用“只能摄影”“不得裁切”的冲突。最后一次零付费补丁将显式设计的次要图形元素与未请求的拼图区分开，当前Composer为v7；已有付费Job不可变快照为v6，未为这一技术措辞补丁重新收费出图。

一次真实修改发现模型把方案版本号猜为2、3，实际版本为1，业务CAS连续拒绝。现由工具绑定本轮读取的拥有者方案快照，模型猜测不再用于写入；如果数据在读取后真正变化，原服务仍拒绝写入，不递增猜版本。修复后从已成功的原生模型回执恢复同一Run，只新发1个图片请求及一次结果审阅，没有新增文本决策收费调用。恢复前后总账本147→149，成功回执与未知费用保护保留。

性能没有宣称改善。对照原套首次规划174.039秒，本轮整套258.593秒，包含Main 7.085秒、Executor 148.199秒和格式修正99.120秒。失败开发候选另耗356.976秒且未提交图片；全部保留在调用证据。已通过确定性编译修复两类无价值的格式重试，但没有再收费重跑整套来宣称新延迟。六图并发生成约28.6–39.2秒/张，主视觉修改只有一个Job。

本轮全部真实试验合计：**K2.8文本11次，图片模型gpt-image-2.5-flare 7次，MCP 0次；文本usage共201,478 Token**，包含失败候选、修正、两次生成后审阅及局部修改。提供方未返回现金API费用，金额记为未知，不按Token猜价格。

当前镜像：backend `director-v2-verified-20261106`，sidecar `director-v2-snapshot-20261106`，frontend `director-v2-20261106`。未新增MySQL表，没有恢复或删除数据卷。管理员LangGraph回退开关保留；回退主控应保留兼容v2 JSON的本版后端，不应直接用尚不认识v2字段的旧后端读取新方案。
