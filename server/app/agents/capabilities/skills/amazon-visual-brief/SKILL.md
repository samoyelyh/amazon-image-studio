professional-aplus-v2按已选官方模块的独立图片槽位交付：模块数不等于图片数。每个槽位保留module_id、slot_id、官方字段、目标/最低像素、独立Prompt、Job/Output及版本。多图文由原生布局组合，不让单次生图画整页文字或格子。原图与原生文案分别导出；HTML只是审核预览，不代表Seller Central真实渲染或发布成功。修改指定模块只更新其必要槽位，其他模块与版本不动。

使用当前方案，必要时读取business.amazon_context。确认模块主卖点、文案、构图、参考素材、桌面/手机适配和禁用内容。服务端根据用户的一次方案确认或“直接生成”要求授权生产，模型不能自行确认。Listing与A+复用同一个方案/生成工具，不逐张请求确认。

用 business.generate_aplus 提交明确的 plan_id、revision 和 module_ids，不默认重做整套。遵循当前execution_policy，普通明确生成不新增费用审批；复用原aplus.generate / JobBatch / Worker / Asset，不访问第三方图片 API。

用户要求重试失败图片时，从方案module_jobs定位失败的模块，设置retry_failed=true，仅提交对应module_ids；已成功和执行中的Job不能重复生成。远端超时/网络/524未知状态不得自动重发，由服务端再次拦截。重复确认同一方案版本复用原Job。

结果通过原会话 Job/Output 展示。失败不得称成功，实际像素以返回 Asset 为准；不把高分辨率生成请求当成合规尺寸保证。图片与文字排版分离，导出前检查规则、文案证据、实际尺寸/格式，人工再审商品保真、英文可读性、授权与双端布局。AI不能代替最终审核。

保留旧输出；单模块调整形成新版本，只生成被选模块。默认交付聊天需求卡和可下载图片/文案清单，不强制Excel，不自动发布到Seller Central。

Prompt是图片生产指令，不是营销文案。检查身份锁、整套风格锁、唯一信息、具体构图、主光/补光、空间尺度、接触阴影和主体层级。不要把泛泛“专业高清”当成艺术指导。
禁止新增版面文字不等于抹掉衣服真实印花、Logo、文字和号码；精确标题/段落/步骤文案交给现有排版工具。
反馈“太暗/商品不突出/构图不合适”时准确定位该模块和当前Output，用business.revise_aplus_module修正相应构图/Prompt，只重做指定模块。旧输出不能变成新的商品事实。
利用personal_experience中的适用偏好和最终通过案例，本次要求和商品事实优先。一次修改只属本任务；明确“以后”才更新长期偏好，不把某件商品错色或错误号码记成通用风格。
